# دليل اختبار الاستعادة المعزولة

## المبدأ التشغيلي

لا تُستعاد أي نسخة احتياطية إلى قاعدة بيانات التشغيل من خلال النظام. تُفك النسخة المشفرة، وتُتحقق بنية الغلاف AES-256-GCM، ثم تُطبَّق فقط على هدف مؤقت منفصل يحمل اسماً عشوائياً. لا يسمح الإجراء بأسماء قواعد بيانات الإنتاج ولا يقبل أي جدول خارج نمط الأسماء الآمن.

## معايير القبول

| الفحص | معيار النجاح |
|---|---|
| سلامة النسخة | فك التشفير والتحقق من الإصدار وبنية الجداول بنجاح |
| عزل الهدف | قاعدة اختبار مستقلة، بلا كتابة إلى قاعدة التشغيل |
| اكتمال الاستعادة | عدد الجداول وعدد الصفوف في الهدف يطابقان بيان النسخة |
| التنظيف | إسقاط قاعدة الاختبار المؤقتة بعد القياس حتى عند فشل التحقق |
| السجل | حفظ وقت البدء والنهاية والنتيجة وعدد الجداول والصفوف دون تضمين أسرار |

## حدود RPO/RTO الحالية

يعتمد **RPO** على وقت آخر نسخة احتياطية مشفرة منشأة يدوياً أو وفق سياسة التشغيل التي سيعتمدها العميل. أما **RTO** فلا يُعلن نهائياً قبل قياس استعادة معزولة ناجحة على حجم بيانات التشغيل الفعلي؛ يسجل الاختبار مدة الاستعادة لتحديد قيمة واقعية.

> لا ينشئ اختبار الاستعادة بيانات تجريبية ولا يغير البيانات التشغيلية. يحتاج التنفيذ إلى صلاحية إنشاء قاعدة بيانات اختبار مؤقتة على خادم قاعدة البيانات نفسه.

## نتيجة الاختبار الأول

في المحاولة المعزولة على النسخة المشفرة الموجودة، رفض مستخدم قاعدة البيانات عملية `CREATE DATABASE` لغياب صلاحية الإنشاء. لم تُنشأ قاعدة مؤقتة ولم تتغير أي بيانات تشغيلية. يلزم منح حساب تشغيل التطبيق صلاحية إنشاء وإسقاط قواعد اختبار مؤقتة، أو توفير قاعدة استعادة منفصلة مخصصة، قبل اعتماد قياس RTO النهائي.
