# مسار ترحيلات Drizzle الرسمي

## الحالة المعتمدة

أصبح ملف `drizzle.config.ts` هو **الإعداد الرسمي الوحيد** لتوليد الترحيلات. يشير إلى:

```text
schema: ./drizzle/schema.ts
out:    ./drizzle-live
```

المجلد `drizzle/` يحتفظ بالمخطط وسجل الترحيلات التاريخي فقط. لا يُشغَّل `drizzle-kit generate` ضده مباشرة لأنه يحتوي snapshots سابقة لا تمثل حالة قاعدة البيانات الحالية وقد يطرح أسئلة إعادة تسمية تفاعلية.

## الأوامر المعتمدة

| الأمر | الاستخدام |
|---|---|
| `pnpm db:generate` | توليد ترحيل من baseline الحالي إلى `drizzle-live/` دون تفاعل |
| `pnpm db:migrate` | تطبيق ملفات الترحيل الجديدة عبر ledger محمي بالـ checksum |
| `pnpm db:baseline` | تسجيل ملفات baseline الموجودة دون إعادة تنفيذ SQL تاريخي؛ يستخدم فقط عند تأسيس بيئة قائمة |
| `pnpm db:workflow-check` | إثبات أن التوليد لا يحتاج إدخالاً تفاعلياً |
| `pnpm db:verify` | تدقيق ledger والمخطط وTypeScript والاختبارات كاملة |

## سياسة التشغيل

لا يُطبق أي ترحيل مُولّد قبل مراجعته. يجب أن يكون كل تعديل بنيوي غير إتلافي أو مصحوباً بخطة ترحيل بيانات وموافقة. عند إضافة عمود أو جدول: يعدّل `schema.ts`، ثم يشغّل `pnpm db:generate`، وتُراجع SQL، ثم يُطبق الترحيل بواسطة المسار المعتمد ويُشغّل `pnpm db:verify`.

> الغرض من `dgtera_migration_ledger` هو منع إعادة تنفيذ ملف ترحيل أو تغيير محتواه بعد اعتماده، ولا يستبدل تدقيق schema أو مراجعة SQL.
