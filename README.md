# دكتره Doktra ERP

نظام ERP محاسبي وتشغيلي متكامل للسوق السعودي، يدعم المحاسبة المالية، المشتريات والمبيعات، المخزون متعدد المواقع، التصنيع وBOM، نقاط البيع للمطاعم، الضريبة المضافة، الصلاحيات الذرية، المصادقة المحلية، التقارير المالية، وطبقة جاهزية تكامل زاتكا.

> هذه الحزمة هي **حزمة مصدر وتسليم** وليست نسخة تحتوي على قاعدة بيانات تشغيلية أو أسرار. بيانات UAT المستخدمة أثناء التطوير ليست ملفاً ضمن الحزمة.

## التقنية

- React 19 + Vite + Tailwind CSS 4
- Express 4 + tRPC 11 + TypeScript 5.9
- Drizzle ORM + MySQL/TiDB
- Vitest للاختبارات
- PWA وواجهة عربية RTL مع دعم الإنجليزية
- جلسات مصادقة محلية باستخدام bcryptjs وJWT

## المتطلبات

- Node.js 22 أو أحدث
- pnpm 10 (الإصدار المحدد في `package.json`)
- MySQL 8 أو TiDB متوافق مع MySQL
- قاعدة بيانات فارغة ومستخدم يملك صلاحية إنشاء/تعديل الجداول

## التشغيل من الصفر

```bash
pnpm install
cp .env.example .env
# عدّل DATABASE_URL وJWT_SECRET وبيانات المالك المحلي داخل .env
pnpm db:push
pnpm dev
```

بعد التشغيل افتح `http://localhost:3000`. المنفذ الافتراضي هو 3000 ويمكن تغييره عبر `PORT`.

## قاعدة البيانات والترحيلات

- المخطط المصدر: `drizzle/schema.ts`
- العلاقات: `drizzle/relations.ts`
- الترحيلات الأساسية: `drizzle/`
- ترحيلات/سجل البيئة الحية: `drizzle-live/`
- أداة الترحيل: `scripts/migrate.mjs`

الأوامر المتاحة:

```bash
pnpm db:migrate       # تطبيق الترحيلات
pnpm db:baseline      # تهيئة baseline عند الحاجة وفق سياسة المشروع
pnpm db:generate      # توليد ترحيلات Drizzle
pnpm db:push          # المسار الموصى به لتجهيز قاعدة جديدة
pnpm db:verify        # فحص الترحيلات، المخطط، TypeScript والاختبارات
```

لا تشغّل `db:baseline` على قاعدة تحتوي بيانات تشغيلية قبل أخذ نسخة احتياطية وفهم حالة الترحيلات.

## بيانات المالك المحلي

يتم إنشاء/تحديث حساب المالك المحلي فقط عند توفير `LOCAL_ADMIN_USERNAME` و`LOCAL_ADMIN_PASSWORD` في بيئة التشغيل. لا توجد كلمة مرور حقيقية داخل هذه الحزمة. يجب على العميل إنشاء كلمة قوية وفريدة وعدم إعادة استخدام قيم التطوير.

## الاختبار والتحقق

```bash
pnpm check
pnpm test
pnpm build
```

تشغيل حزمة التحقق الشاملة يحتاج `DATABASE_URL` صالحاً وبعض الاختبارات التي تتصل بقاعدة البيانات:

```bash
pnpm db:verify
```

## الإنتاج

```bash
pnpm install --frozen-lockfile
cp .env.example .env
# املأ الأسرار وقاعدة البيانات في بيئة إدارة أسرار آمنة
pnpm db:migrate
pnpm build
NODE_ENV=production pnpm start
```

يجب وضع التطبيق خلف HTTPS ووكيل عكسي، وتفعيل نسخ احتياطية دورية، وتقييد الوصول إلى قاعدة البيانات، وتدوير الأسرار قبل الإنتاج.

## الخدمات والتكاملات

- MySQL/TiDB: التخزين الأساسي.
- خدمات Manus المدمجة اختيارية لوظائف التخزين والخرائط والصور والصوت وData API؛ أسماء متغيراتها موجودة في `.env.example`.
- ZATCA/FATOORA: توجد طبقة بيانات وإجراءات جاهزية داخل النظام، لكن الاعتماد الرسمي يتطلب إعداد منشأة العميل وCSR/CSID وبيئة الاختبار والموافقات الرسمية. لا توجد شهادات أو مفاتيح ZATCA في هذه الحزمة.

## بنية المشروع

| المسار | الدور |
|---|---|
| `client/` | واجهة React والصفحات والمكونات وPWA |
| `server/` | خادم Express وtRPC، منطق الأعمال، المصادقة والاختبارات |
| `drizzle/` | مخطط قاعدة البيانات والترحيلات الأساسية |
| `drizzle-live/` | ترحيلات مرتبطة بسجل البيئة الحية |
| `scripts/` | الترحيل، UAT، والتحقق التشغيلي |
| `docs/` | تقارير التقييم وخطط الجاهزية والتوثيق الفني |
| `shared/` | الأنواع والثوابت المشتركة |
| `patches/` | ترقيعات الاعتماديات المطلوبة |

## ملاحظات التسليم

- لا تتضمن الحزمة `node_modules` أو `.git` أو السجلات أو ملفات build القديمة أو ملفات `.env`.
- لا تتضمن الحزمة نسخة قاعدة بيانات أو بيانات عملاء تشغيلية.
- راجع `HANDOVER.md` للتفاصيل التشغيلية والبوابات المؤجلة.
- راجع `DELIVERY_CHECKLIST.md` لسجل التحقق النهائي.
